# Общая сессия Go в линии 1.x.x

Это существующее приложение `pob2_ui`. Ветка `1.x.x` предназначена для перехода
на `pob2_engine`; `main` сохраняет прежнюю линию 0.x. Подготовленная версия
`1.0.0+49` ещё не выпущена. Теги `v1.*` публикуются только из истории `1.x.x`.
Обычный редактор использует исходный Lua. Общая сборка открывается отдельно и показывает сохранённый расчёт движка сессий.

## Подключение

1. Соберите `pob2_engine` с контрактом `session.events`:
   `go build -o pob2-engine ./cmd/pob2-engine` (Windows: `pob2-engine.exe`).
   API приложения закреплён на ревизии в `pubspec.yaml`.
2. Нажмите значок связи слева в нижней строке состояния. Выберите программу,
   профиль сервера и явный `session_id`. Можно задать программу переменной
   окружения `POB2_ENGINE_EXECUTABLE` перед запуском приложения.
3. Подключитесь к существующей сессии либо явно включите «Создать новую сессию».
   Отсутствующий сервер профиля запускается автоматически с сохранением на диск. При создании можно
   импортировать открытую сборку вместе с XML заметок и этапов прокачки.
4. Для синхронизации имени открытой XML-сборки включите «Связать с открытой
   сборкой». При подключении применяется имя сервера; при смене сборки привязка
   отключается. Без привязки изменения видны в строке состояния и диалоге.

## Условия в штатной мастерской

При создании сессии включите импорт и привязку открытой сборки, чтобы
синхронизировать XML. Для существующей сессии привязку XML можно включить
флажком «Заменить открытую сборку снимком сессии». При подключении приложение
сохранит прежнюю версию файла средствами библиотеки и примет снимок сервера.

Штатный редактор условий использует текущую ревизию сессии. PoB II
пересчитывает принятый XML через Lua и сохраняет его в библиотеке. Изменение
через MCP или CLI также приходит в мастерскую. Если другая правка пришла
после открытия формы, откройте редактор заново. Если XML-файл изменился
отдельно от сессии, сохранение останавливается до проверки версий и повторного
подключения. Поиск условий и разбор данных отчёта пока выполняет прежний Lua.
Этапы прокачки по-прежнему хранятся в библиотеке PoB II. Движок
сохраняет XML без комментариев за пределами корневого элемента.

## Обычные пассивы в штатном дереве

После привязки XML в PoB II нажмите обычный пассив на штатном дереве.
Движок `v0.0.12` покажет затронутые узлы, очки и изменение показателей.
Назначение использует выбранный режим дерева, снятие — режим, в котором
пассив уже назначен. После применения мастерская обновит дерево и запишет
подтверждённый XML в библиотеку. Если сессия изменилась, перед применением
нужно заново запросить предпросмотр.

Движок с возможностью `build.tree_sockets` также назначает и снимает
пустые гнёзда. Для гнезда мастерская выбирает общий режим независимо от
выбранной вкладки оружия. Для правки занятого гнезда сначала выньте самоцвет.
Проверить этот сценарий можно в процессном тесте с `POB2_ENGINE_TEST_SOCKETS=1`.

В движке с возможностью `build.tree_jewels` откройте карточку назначенного
гнезда правой кнопкой мыши и выберите «Самоцвет». Можно выбрать предмет
из сборки, вставить его текст или снять установленный самоцвет.
Предпросмотр показывает изменение расчёта, после применения снятый
предмет остаётся в сборке. Для процессной приёмки задайте
`POB2_ENGINE_TEST_JEWELS=1` и укажите бинарник с этой возможностью.

Меню «Набор дерева» переключает существующие спецификации общей сборки
при наличии `build.tree_specs`. При выборе обновляются класс, узлы и
расчёт. Перед записью проверяется ревизия, с которой открыли меню.
Для процессной проверки задайте `POB2_ENGINE_TEST_TREE_SPECS=1`.

Выбор атрибутов на штатном дереве продолжает работать через прежний Lua.

Сборка движка пока поставляется отдельно. До включения её в установщики первый
стабильный выпуск 1.x не считается готовым к публикации.

## Поведение

Правки CLI и MCP `--attach` должны использовать тот же профиль и сессию.
Строка состояния показывает имя, ревизию и последнюю правку «Было → Стало»;
диалог хранит восемь последних событий. Привязанное имя сохраняется в библиотеке.
Переименование в UI и отмена имени отправляются в общий сервис с ожидаемой
ревизией; внешнее событие не отправляется обратно второй командой.

При обрыве клиент повторяет обнаружение и читает все события после последней
применённой ревизии. Снимок более старой сессии требует явного переподключения.
Ошибки записи и повтор успешной команды событий не добавляют. В общей сборке синхронизируется уровень персонажа. Другие поля можно править через MCP.

Дочерний `connect --kind ui --connection-json` удерживает одну аренду приложения
до закрытия stdin. Адрес, токен и аренда передаются только через приватный канал
процесса; они не сохраняются в настройках и не выводятся в журнал приложения.

## Проверки

`flutter test test/engine_session_test.dart` проверяет виджет, переподключение и
привязку. Для настоящих CLI/MCP задайте `POB2_ENGINE_TEST_EXECUTABLE` и выполните
`flutter test test/engine_session_process_test.dart`. CI запускает процессный
сценарий на Linux. Эти проверки подтверждают транспорт, а не игровые расчёты Go.

С отдельным `POB2_UI_HOME` и установленными Lua и MCP процессный тест
также проверяет сохранение условия из штатного редактора, внешнюю правку,
отклонение устаревшей формы и восстановление после перезапуска движка.
Там же проверяются назначение и снятие пассива в общем режиме и обеих ветвях
оружия, неизменность XML во время предпросмотра и отказ по старой ревизии.

Для сквозной проверки в нативном окне задайте `POB2_ENGINE_TEST_EXECUTABLE`
и отдельный `POB2_UI_HOME` с установленной парой Lua PoB и MCP. Запустите
`flutter test integration_test/engine_session_desktop_test.dart -d windows`.
Тест открывает копию XML из набора примеров, подключает окно к общей сессии,
проверяет применение имени из MCP в интерфейсе и библиотеке, а затем читает
через MCP имя, изменённое пользователем в окне PoB II.

## Открытие полной сборки

Создайте сессию с XML через `pob2-engine session create --file build.xml` и
укажите привычные параметры профиля, имени и идентификатора. Подключите
приложение и выберите «Открыть общую сборку» в диалоге сессии. Здесь можно
изменить уровень, запустить расчёт и сохранить XML в выбранное место. В окне
показываются результат актуальной ревизии и предупреждения PoB. При конфликте
подписка доставляет новое состояние, а пропущенную правку можно повторить
явно. Исходный XML остаётся отдельным от редактируемой сессии.
## Камни поддержки

При подключении к движку с возможностью `build.add_support` в окне общей
сборки доступна кнопка «Добавить поддержку». Выберите камень из каталога,
уровень и качество, затем выполните предпросмотр. В окне видны показатели до
и после добавления, их разница и диагностика PoB. При смене ревизии или
переподключении выполните предпросмотр заново. Принятая правка появляется
в снимке по подписке. Новый итоговый расчёт запускается кнопкой «Рассчитать».

Для проверки поддержек запустите настольный тест с
`POB2_ENGINE_TEST_SUPPORT=1` и бинарником движка. В GitHub Actions укажите `engine_release`
и включите `engine_support` при ручном запуске проверок.

## Экипировка

С возможностью `build.equipment_preview` раздел «Экипировка» окна общей
сборки открывает примерку для слота брони или украшений. Вставьте текст
предмета или отметьте «Снять», выполните предпросмотр и сравните показатели.
Предупреждения и нераспознанные свойства показывает PoB. При новой
ревизии или переподключении выполните предпросмотр заново.

Для нативного теста с движком 0.0.9 задайте `POB2_ENGINE_TEST_EQUIPMENT=1`.
В GitHub Actions укажите `engine_release` и включите `engine_equipment`.

## Дерево пассивов

С возможностью `build.tree_preview` откройте «Дерево пассивов» в окне
общей сборки. Найдите узел по имени из каталога PoB или по ID. Окно
предлагает назначить свободный узел или снять уже назначенный. Предпросмотр
показывает ID всех затронутых узлов, изменение показателей и предупреждения.
Если сборка изменилась или приложение переподключилось, сравните заново
перед подтверждением. После правки новая ревизия приходит по подписке.

При разработке с соседней копией движка в `../pob2_engine` подключите
новый Dart API через локальный `pubspec_overrides.yaml`.

```yaml
dependency_overrides:
  pob2_engine_api:
    path: ../pob2_engine/gen/dart
```

Для сквозной проверки задайте `POB2_ENGINE_TEST_TREE=1` и укажите
собранный движок в `POB2_ENGINE_TEST_EXECUTABLE`. В GitHub Actions
доступен параметр `engine_tree`.

## Атрибуты пассивов

С возможностью `build.tree_attributes` в окне дерева можно выбрать силу,
ловкость или интеллект при назначении узла либо изменить атрибут
уже назначенного пассива. Предпросмотр показывает изменения атрибутов по
узлам и показатели сборки. Новый выбор или новая ревизия требуют повторного
предпросмотра перед применением.

Для сквозного теста задайте `POB2_ENGINE_TEST_ATTRIBUTES=1`. В GitHub Actions
укажите `engine_release` и включите `engine_attributes`.

## Ветви комплектов оружия

С возможностью `build.tree_allocation_modes` можно выбрать общие пассивы,
оружие I или оружие II. Для назначенного узла окно показывает его текущий
режим. Предпросмотр показывает затронутые узлы, расход очков и расчёт
для активного оружия. После смены активного оружия нужен новый предпросмотр.

Для сквозного теста задайте `POB2_ENGINE_TEST_WEAPON_MODES=1`.
В GitHub Actions укажите `engine_release` и включите `engine_weapon_modes`.
Dart API закреплён на коммите кандидата `v0.0.12-rc.1`.

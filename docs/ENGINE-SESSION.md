# Общая сессия Go в линии 1.x.x

Это существующее приложение `pob2_ui`. Ветка `1.x.x` предназначена для перехода
на `pob2_engine`; `main` сохраняет прежнюю линию 0.x. Подготовленная версия
`1.0.0+49` ещё не выпущена. Теги `v1.*` публикуются только из истории `1.x.x`.
Игровые расчёты пока выполняет исходный Lua; Go поддерживает сессии и их имена.

## Подключение

1. Соберите `pob2_engine` с контрактом `session.events`:
   `go build -o pob2-engine ./cmd/pob2-engine` (Windows: `pob2-engine.exe`).
   API приложения закреплён на ревизии в `pubspec.yaml`.
2. Нажмите значок связи слева в нижней строке состояния. Выберите программу,
   профиль сервера и явный `session_id`. Можно задать программу переменной
   окружения `POB2_ENGINE_EXECUTABLE` перед запуском приложения.
3. Подключитесь к существующей сессии либо явно включите «Создать новую сессию».
   Отсутствующий сервер профиля запускается автоматически с сохранением на диск.
4. Для синхронизации имени открытой XML-сборки включите «Связать с открытой
   сборкой». При подключении применяется имя сервера; при смене сборки привязка
   отключается. Без привязки изменения видны в строке состояния и диалоге.

Сборка движка пока поставляется отдельно. До включения её в установщики первый
стабильный выпуск 1.x не считается готовым к публикации.

## Поведение

Правки CLI и MCP `--attach` должны использовать тот же профиль и сессию.
Строка состояния показывает имя, ревизию и последнюю правку «Было → Стало»;
диалог хранит восемь последних событий. Привязанное имя сохраняется в библиотеке.
Переименование в UI и отмена имени отправляются в общий сервис с ожидаемой
ревизией; внешнее событие не отправляется обратно второй командой.

При обрыве клиент повторяет обнаружение и читает все события после последней
применённой ревизии. Снимок более старой сессии требует явного переподключения.
Ошибки записи и повтор успешной команды событий не добавляют. Изменения других
полей Lua пока не передаются через Go и не считаются синхронизированными.

Дочерний `connect --kind ui --connection-json` удерживает одну аренду приложения
до закрытия stdin. Адрес, токен и аренда передаются только через приватный канал
процесса; они не сохраняются в настройках и не выводятся в журнал приложения.

## Проверки

`flutter test test/engine_session_test.dart` проверяет виджет, переподключение и
привязку. Для настоящих CLI/MCP задайте `POB2_ENGINE_TEST_EXECUTABLE` и выполните
`flutter test test/engine_session_process_test.dart`. CI запускает процессный
сценарий на Linux. Эти проверки подтверждают транспорт, а не игровые расчёты Go.

# Данные и готовое дерево Lua

Проверенная пара 6 ноября 2026: PoB `v0.23.1`, Git `7d6f530cbdab20389ff8bc6ba97a37ac27f74e41`; MCP `v0.12.0`, Git `86f7f1e42e09078cce279580f9c4ea80aae82db1`. Компоненты устанавливаются отдельно от интерфейса. Первый публичный выпуск приложения — `0.1.0+1`.

`pob_check_build` возвращает `report.source = original-lua`, `stats`, `snapshot.buildInfo`, `groups`, `items`, `slots`, `config`, `warnings` и `customMods`. `BuildReport` проверяет источник; отсутствующее число показывается прочерком. Настоящий ноль остаётся нулём. Предупреждения объединяют общие сообщения, ошибки камней, неподдерживаемые строки предметов и пользовательских модификаторов.

## Каталоги умений и условий

`GameCatalogRepository` читает все страницы `pob_catalog` по 200 записей, объединяет повторяющиеся ID и кеширует результат до переподключения компонентов. Поиск учитывает исходное название, ID и доступный перевод. В проверенной паре каталог содержит 966 камней и 560 строк условий, из которых 559 имеют уникальный ID. Эти количества не закреплены в интерфейсе.

`pob_add_skill_group` принимает точные ID камней, целые уровень/качество и логическое состояние. `pob_update_skill_group` изменяет существующую группу по `groupId`, сохраняя исходные параметры группы и камней через `sourceIndex`. `pob_delete_skill_group` вызывает исходный обработчик удаления PoB; выбор оставшегося основного умения также определяет Lua. Правила совместимости, диапазоны значений и расчёт остаются в Lua/MCP. Ошибки камней и предупреждения показываются из отчёта. Прямое редактирование игровых секций XML во Flutter не используется.

На широком экране слева расположен список групп со всеми камнями, справа — каталог совместимых поддержек выбранного умения. На узком экране доступны вкладки. Перенос из каталога в группу сразу сохраняет добавление, обратный перенос убирает поддержку. Галочка у названия задаёт основную группу через `pob_select_main_skill`. Корзина удаляет группу; история XML позволяет отменить удаление, в том числе последней группы, и повторить его.

Нажатие названия или камня открывает редактор существующей группы. В нём активный камень всегда первый, поддержки рядом; их порядок меняется со стабильными ключами. Параметры поддержки открываются нажатием на её иконку; поля сохраняются при перестановке. Отпускание вне ячеек ничего не меняет. До подтверждения это локальный черновик. Форма рассчитана на один активный камень; группы от предметов и группы с несколькими активными камнями не изменяются этой формой.

`pob_gem_icons` принимает пакеты до 24 ID и возвращает base64 `data`, `mimeType` и `source`. Активные иконки берутся из ресурсов PoB. Для отсутствующих там изображений поддержек GGG используется закреплённый по SHA-256 каталог [PoE2DB](https://poe2db.tw/us/Support_Gems), с отдельной загрузкой и кешем. В Git приложения изображения не входят. Ошибка показывает возможность повтора, а не условную замену. Игровые характеристики из внешнего источника не используются.

`support` каталога MCP 0.10.0 берётся из `gem.grantedEffect.support`. `pob_gem_supports` открывает копию текущего XML в отдельной сессии Lua, добавляет пробную группу и вызывает исходный `calcLib.canGrantedEffectSupportActiveSkill` для её `displaySkillList`, как `GemSelectControl`. Рабочая сборка и ревизия не меняются. Запросы формы объединяются при быстром вводе; устаревший ответ не меняет текущий фильтр. После смены умения неподходящие выбранные поддержки отмечены, подтверждение недоступно до исправления. Вместимость и рекомендации ещё требуют публичного контракта; интерфейс не выводит их самостоятельно.

Условия читаются из полного каталога `config`, включая ещё не заданные параметры. Отсутствие в `report.config` отображается как «По умолчанию». Типы `check`, `list`, `text`, `count`, `countAllowZero`, `integer`, `float` определяют поля формы; значения списка передаются без замены метками. Повторяющиеся варианты объединяются по значению, неизвестное текущее значение не подставляется в список. Числовой ввод проверяется на тип и конечность; игровые ограничения проверяет `pob_set_config`.

После изменения отчёт пересчитывается и сохраняется в библиотеку; только затем пополняется Undo и очищается Redo. При отказе выполняется восстановление предыдущего XML, форма сохраняет ввод и показывает ошибку. Обычное закрытие приложения во время записи или при незавершённой форме отменяется; пользователь может закончить изменение либо явно отменить форму.

## Оригинальная сцена

`pob_get_tree({includeScene: true})` возвращает координаты и идентификаторы узлов, связи, типы, состояния, размеры и названия, а также готовую сцену `PassiveTreeView.Draw`. Она содержит исходные фоны, портреты, дуги, рамки, эффекты и иконки. Flutter не строит игровое дерево самостоятельно.

Команда сцены содержит позиции четырёх вершин, UV, цвет, режим смешивания и непрозрачный токен текстуры. `pob_tree_textures({token})` возвращает base64 PNG RGBA только для ресурса выданной сцены. Произвольные пути не принимаются. DDS BC1/BC7 декодирует MCP; большие текстуры используют mip-уровни для ограничения памяти. Маски, которые пока не поддерживаются, дают явную ошибку.

Flutter записывает готовые команды в `ui.Picture`. Масштабирование, перенос и поиск работают поверх оригинальной сцены. Постоянных подписей нет. При наведении `pob_tree_hover` возвращает оригинальную подсказку `AddNodeTooltip` и небольшой слой оригинальной подсветки пути или зависимых узлов. Названия и изменения показателей приходят из установленного PoB на его языке. Клик назначает путь или возвращает узел через Lua; удержание открывает подробности. Указания клавиатуры оригинального окна PoB, которые здесь не поддерживаются, в подсказке скрыты. Системное уменьшение движения отключает переходы и плавное приближение.

Ресурсы кешируются в пользовательском каталоге `tree-cache/` по полной паре Git-ревизий, версии дерева и токену. Исходные игровые ресурсы в Git приложения не включаются. После обновления пары используется другой кеш. Первая загрузка показывает прогресс.

## Действия и состояние

- `pob_tree_action` назначает путь или возвращает узел; стоимость и допустимость определяет Lua. Для атрибутного узла пользователь выбирает вариант из каталога.
- `pob_select_main_skill` переключает доступные группу, умение и часть.
- `pob_set_config` принимает значение формы, тип и варианты которой прочитаны через `pob_catalog`.
- `pob_export_xml` и `pob_import_xml` сохраняют и восстанавливают состояние. Библиотека хранит несколько XML и метаданные; рабочая сессия восстанавливается при подключении.

При изменении или обрыве соединения предыдущий отчёт отмечается устаревшим. Неудачное действие не выглядит новым успешным расчётом. Потерянный ответ на изменение не вызывает автоматического повторения команды.

Полные редакторы предметов и групп камней, выбор эффекта мастерства остаются задачами следующих этапов. Успешный расчёт PoB не означает проверку сборки в игре.

## Воспроизведение

`dart run tool/smoke.dart --install` проверяет установленную пару, исходный Lua, XML, настоящие узлы и все текстуры сцены. С отдельным `POB2_UI_HOME` команда `flutter test integration_test/workspace_test.dart -d windows` проверяет загрузку ресурсов Flutter, наведение, подсказку, подсветку длинного пути, назначение/возврат по клику в оригинальной сцене, пересчёт, XML и пять разделов интерфейса. CI запускает соответствующий сценарий на Windows/Linux/macOS. Ширины 360, 768, 1366 и 1920 px отдельно покрываются тестами виджетов.

## Поиск влияния узлов

`pob_node_power` работает в сессии `engine` и использует исходные `CalcsTab:PowerBuilder`, `TreeTab:BuildPowerReportList` и `PassiveTreeView.Draw`. Каталог характеристик приходит из Lua. Расстояние — исходное число очков пути; значения эффекта, форматированные строки, влияние на очко, сортировка и цвета тепловой карты рассчитываются в PoB. Flutter не повторяет эти формулы.

Интерфейс вызывает `catalog`, затем `start` с характеристикой и ограничением расстояния, опрашивает `poll` до завершения. Для полного дерева ограничение отсутствует. Доступны фильтры выбранных/невыбранных узлов и отмена по идентификатору задания. Ответ содержит готовую сцену и строки отчёта; нажатие строки только перемещает вид. При изменении сборки список сохраняется, фильтр обновляется, а эффекты и пути пересчитываются через Lua; прежние значения помечаются устаревшими. При смене параметров или закрытии панели отчёт сбрасывается. Устаревшие ответы не отображаются.

Основная прямоугольная подложка `main:DrawBackground` не рисуется во Flutter: вся область дерева, включая свободные участки за границей сцены, залита единым почти чёрным цветом PoB `#080C11`. Портреты и остальные текстуры сохраняются. Четыре пары значений исходной `pointDisplay` подписаны как пассивные очки, наборы оружия I/II и восхождение; числовые лимиты не вычисляются в Dart.

`attributeOptions[].id` обозначает узел, а для назначения атрибута Lua принимает индекс варианта 1–3. Панель с иконками использует порядок исходного списка.

## Оформление

Выбор светлой/тёмной темы хранится отдельно в `appearance.json` и загружается до первого кадра. Тёмная палитра взята из [morhetz/gruvbox](https://github.com/morhetz/gruvbox/blob/master/colors/gruvbox.vim). Фон, поверхности, кнопки, векторные ресурсы и подсказки переключаются вместе. Цвета текста подсказок адаптируются к палитре и проверяются на контраст 7:1 с учётом прозрачности подложки; игровые значения и исходные текстуры не изменяются.

## Окно приложения

Windows сохраняет обычную геометрию и развёрнутое состояние в `window-state.bin` пользовательского профиля; при отключении монитора окно возвращается на доступный экран. Настоящий запуск проверяется `python tool/check_window_state.py`. Linux сохраняет `window-state.ini` через GTK, macOS использует системное сохранение рамки NSWindow. В Wayland compositor управляет положением окна: восстановление размера доступно, произвольное размещение может ограничиваться средой рабочего стола.

## XML, заметки и сохранность данных

Ctrl+O и Ctrl+S вызывают системные диалоги через официальный `file_selector`; вставка и копирование XML доступны в меню «Ещё». Файлы больше 16 МБ и пустой XML отклоняются до импорта. Содержимое проверяется исходным Lua. Новый файл становится активной сборкой только после расчёта и фиксации библиотеки; ошибка возвращает предыдущий XML в Lua и сохраняет историю Undo/Redo.

`builds/index.json` хранит ссылку `revision` на неизменяемый XML в `builds/revisions/`. Новая ревизия записывается до атомарной замены индекса; предыдущая остаётся доступной при сбое. Старый формат с `builds/<id>.xml` мигрирует без удаления файлов. Совместимая копия остаётся для прежних версий приложения. Запуск сначала восстанавливает активную ревизию библиотеки; резервная сессия импортируется отдельной сборкой, если активная недоступна.

`notes/<id>.md` и `draft.xml` записываются последовательной очередью с объединением последнего ввода. Ошибка удерживает текст для повтора. Заметки локальные, копируются при дублировании сборки и не входят в игровой XML. История игровых действий их не изменяет. Для изменяемых текстовых файлов сохраняется `.bak`.

`ExitProtection` завершает запись через `checkpoint` перед обычным закрытием окна. На Windows оболочка перехватывает `WM_CLOSE` и ждёт разрешения Dart через канал `pob2_ui/window`; на macOS закрытие окна направлено в штатное завершение приложения, на Linux используется штатный запрос Flutter. Ошибка отменяет выход; незавершённая операция также требует дождаться результата. Обновление приложения использует тот же `checkpoint`. Это защита обычного закрытия и ошибок записи, без гарантии сохранения последнего ввода при принудительном завершении процесса или отключении питания.

Проверка 6 ноября 2026 года: ревизия `957eb9bde4b6ba746d933a67290f4946dd50dd31`, [полностью успешный CI](https://github.com/Hecatoncheir/pob2_ui/actions/runs/42168185024). На Windows прошли 106 тестов; на Linux/macOS — 105 и один штатно пропущенный тест сбоя загрузки компонентов, предназначенный для Windows. Проверены анализ, форматирование, предел сложности 10, сборки трёх ОС, установщики `.exe`/`.dmg`/`.run`, их установка и запуск, `smoke --install` и интеграционный сценарий с настоящим Lua. Пара: PoB `7d6f530cbdab20389ff8bc6ba97a37ac27f74e41`, MCP `ded473508f66f88209b399489916eb6919836187`.

Сценарий проверяет дерево, Undo/Redo, атрибуты, оружейные режимы, поиск влияния узлов, файловый XML, отказ повреждённого XML, восстановление отчёта и заметок, языки и масштаб. Общий предел Linux/macOS — 8 минут, Windows — 4; журнал содержит длительность этапов. Лимит macOS увеличен после превышения четырёх минут на CI при успешно пройденных этапах дерева, атрибутов, оружия, тем и влияния узлов; состав проверок сохранён. В CI путь файла подставляется через `XmlFileDialogs`, но файловая система и Lua используются настоящие. Ручная проверка самих системных диалогов Linux/macOS остаётся открытой.

Через системные диалоги Windows сохранён и вновь открыт XML. В отдельном Release-окне запрет записи `draft.xml` отменил Alt+F4 с сообщением об ошибке; после восстановления доступа повторный выход сохранил исходный текст и закрыл окно. Этот отказ и повтор закреплены в `tool/check_window_state.py` и успешно проверены в CI.

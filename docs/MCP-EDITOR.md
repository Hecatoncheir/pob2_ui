# Управление PoB II через MCP

Шлюз включается пользователем в «Правки через MCP» или явным локальным флагом запуска приложения `--mcp-editor`. Разрешение действует только для текущего запуска; MCP не может включить доступ сам. Скопированная команда запускает совместимый MCP с `--mode editor` и локальным `endpoint.json`. Для расширенных команд нужны MCP 0.22.0 **и** PoB II 0.10.3 или новее.

Начальная команда — `pob_editor_status`. Она возвращает подключение Lua, занятость, диалог, ID сборки, ревизию, историю, компоненты, интерфейс, возможности и последние сообщения. Статус доступен при занятом приложении. Чтение Lua разрешено при открытом диалоге и свободном движке. Изменения используют ревизию клиента; после `STALE_REVISION` нужно заново прочитать статус или отчёт.

Поддержаны команды приложения (`pob_editor_app`), компонентов (`pob_editor_components`), результата фоновой задачи (`pob_editor_job`), библиотеки (`pob_editor_library`), Undo/Redo (`pob_editor_history`), заметок (`pob_editor_notes`), файлов/кодов/ссылок (`pob_editor_files`), этапов прокачки (`pob_editor_progression`) и интерфейса (`pob_editor_ui`). Точный перечень действий и параметров объявляет MCP через `tools/list`; доступность в открытом приложении сообщает `capabilities`.

Графический интерфейс передаёт навигацию и настройки своим Bloc, файловые и библиотечные операции — существующим хранилищам, игровые изменения — исходному Lua. Открытие/копирование/импорт сборки по команде MCP сохраняет канал и меняет привязку к новой сборке. Ручное переключение сборки отключает доступ.

С PoB II 0.11.0 `pob_editor_files` с `action: import_link` импортирует экспорты PoB с pobb.in, poe.ninja и прежнего poe2.ninja. Для страниц профилей и персонажей poe.ninja команда сохраняет текущую сборку и возвращает `imported: false`, `requires: pob_code`, `sourceUrl` и `nextAction: import_code`. Это запрос к пользователю на получение кода через Copy PoB code на сайте, а не успешный импорт. После получения кода вызовите `import_code` с ним в `text`. Внутренний API профилей не вызывается.

Смена компонентов выполняется фоном. Ответ содержит номер задачи; `pob_editor_job` возвращает `running`, затем `complete` с результатом либо `failed` с ошибкой. Проверяются запуск Lua, импорт текущего XML, сохранение класса и доступность дерева. Проверка проходит до активации. При отказе остаются старая пара, сборка и история. Выбрать можно только зарегистрированный установленный компонент по commit. Для замены dev закреплённым стабильным выпуском нужен `allowReplaceDev=true`. Проверка обновлений использует версии, закреплённые в приложении.

Обычные команды дерева, экипировки, умений, конфигурации и пользовательских модификаторов сохраняются тем же механизмом, что правки пользователя. Доступны все чтения движка: каталоги, подсказки, ресурсы/сцена дерева, изображения, сила узлов, поддержки и их предварительный расчёт, сравнение предметов и торговый поиск. Готовые изображения передаются из сессии движка вместе с ответом MCP.

PoB II 0.13.0 и MCP 0.24.1 добавляют чтение `pob_compare_supports`: полная группа, выбранный активный камень и до восьми кандидатов рассчитываются из одного XML. Возвращаются DPS до/после, разница, отдельные ошибки и предупреждения, `xmlHash` и `baseRevision`. Чтение не сохраняет сборку и не добавляет Undo/Redo. `pob_gem_supports` с `targetIndex` возвращает совместимость полной группы и фактический состав `sockets`; неизвестная вместимость остаётся `null`. [Контракт](LUA-CONTRACT.md#состав-группы-и-сравнение-поддержек-в-v0130).

С PoB II 0.12.0 и MCP 0.23.0 `pob_editor_ui` возвращает `uiProtocol: 1` и управляет любым разделом и диалогом Flutter через обычные обработчики приложения:

- `snapshot`: актуальные `snapshotId`, `dialogOpen`, размер `viewport` и элементы `nodes` с подписями, значениями, состояниями, ID и доступными `actions`/`customActions`.
- `perform`: `nodeId`, свежий `snapshotId` и `operation` из действий элемента. Для ввода сначала `tap` на поле, затем `setText` с `value`; сохранение и применение — нажатие обычной кнопки формы. `setSelection` принимает `{base, extent}`, `scrollToOffset` — `{x, y}`, `customAction` — ID из снимка.
- `screenshot`: PNG окна как изображение MCP, вместе со снимком элементов. Размер PNG соответствует логическим пикселям `viewport`.
- `gesture`: `tap`, `doubleTap`, `longPress`, `hover`, `scroll` и `drag` по координатам `from: {x, y}`; для `drag` добавляется `to`, для прокрутки — `value: {x, y}`, для правой кнопки — `button: secondary`.
- `key`: клавиша `key` и необязательные `modifiers: [control, shift, alt, meta]`. Поддержаны печатные ASCII-клавиши, F1–F24 (`f1`–`f24`), Tab/Enter/Escape, пробел, удаление, стрелки, Home/End/PageUp/PageDown. Например, `key: z, modifiers: [control]` вызывает обычную отмену. `modifiers` также применяются к `gesture`, например Shift + нажатие или Ctrl + прокрутка.
- `close_dialog`: закрытие верхнего диалога, включая «Полный DPS». Для явной отмены формы с редактируемым полем нужен `discard: true`; сохранить её можно через кнопку. Учитывается защита закрытия самой формы.

`perform`, `gesture` и `key` требуют свежий `snapshotId` и возвращают следующий снимок. После `STALE_UI` получите новый снимок; старые ID не переиспользуйте. Прямые изменения Lua остаются защищены, пока открыта форма; действия самой формы разрешены. Авторизованная смена сборки через её кнопки сохраняет канал MCP. Рисованные панели доступны через жесты, а дерево и игровые данные — также через отдельные инструменты Lua.

Системные окна выбора файлов не входят в Flutter. Операции открытия, импорта, сохранения и экспорта без них выполняются через `pob_editor_files` с явным путём. Завершение и перезапуск выполняются после сохранения и отправки ответа HTTP. Отзыв доступа также происходит после ответа. После перезапуска разрешение включается вручную. Экспорт требует абсолютного пути и `overwrite=true` для замены файла; хранилище не позволяет затереть существующую сборку библиотеки экспортом.

Проверки: `flutter test`, `flutter analyze`, `python tool/check_complexity.py`, `flutter test integration_test/mcp_editor_test.dart -d windows`. Сквозному тесту нужен отдельный `POB2_UI_HOME` с установленной совместимой парой. Проверяются вычисления PoB и управление приложением, не поведение сборки в игре.

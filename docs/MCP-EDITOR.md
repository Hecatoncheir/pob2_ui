# Управление PoB II через MCP

Шлюз включается пользователем в «Правки через MCP» или явным локальным флагом запуска приложения `--mcp-editor`. Разрешение действует только для текущего запуска; MCP не может включить доступ сам. Скопированная команда запускает совместимый MCP с `--mode editor` и локальным `endpoint.json`. Для расширенных команд нужны MCP 0.22.0 **и** PoB II 0.10.0 или новее.

Начальная команда — `pob_editor_status`. Она возвращает подключение Lua, занятость, диалог, ID сборки, ревизию, историю, компоненты, интерфейс, возможности и последние сообщения. Статус доступен при занятом приложении. Чтение Lua разрешено при открытом диалоге и свободном движке. Изменения используют ревизию клиента; после `STALE_REVISION` нужно заново прочитать статус или отчёт.

Поддержаны команды приложения (`pob_editor_app`), компонентов (`pob_editor_components`), результата фоновой задачи (`pob_editor_job`), библиотеки (`pob_editor_library`), Undo/Redo (`pob_editor_history`), заметок (`pob_editor_notes`), файлов/кодов/ссылок (`pob_editor_files`), этапов прокачки (`pob_editor_progression`) и интерфейса (`pob_editor_ui`). Точный перечень действий и параметров объявляет MCP через `tools/list`; доступность в открытом приложении сообщает `capabilities`.

Графический интерфейс передаёт навигацию и настройки своим Bloc, файловые и библиотечные операции — существующим хранилищам, игровые изменения — исходному Lua. Открытие/копирование/импорт сборки по команде MCP сохраняет канал и меняет привязку к новой сборке. Ручное переключение сборки отключает доступ.

Смена компонентов выполняется фоном. Ответ содержит номер задачи; `pob_editor_job` возвращает `running`, затем `complete` с результатом либо `failed` с ошибкой. Проверяются запуск Lua, импорт текущего XML, сохранение класса и доступность дерева. Проверка проходит до активации. При отказе остаются старая пара, сборка и история. Выбрать можно только зарегистрированный установленный компонент по commit. Для замены dev закреплённым стабильным выпуском нужен `allowReplaceDev=true`. Проверка обновлений использует версии, закреплённые в приложении.

Обычные команды дерева, экипировки, умений, конфигурации и пользовательских модификаторов сохраняются тем же механизмом, что правки пользователя. Доступны все чтения движка: каталоги, подсказки, ресурсы/сцена дерева, изображения, сила узлов, поддержки и их предварительный расчёт, сравнение предметов и торговый поиск. Готовые изображения передаются из сессии движка вместе с ответом MCP.

`close_dialog` закрывает только текущий диалог разрешения MCP; ввод в других диалогах защищён. Завершение и перезапуск выполняются после сохранения и отправки ответа HTTP. Отзыв доступа также происходит после ответа. После перезапуска разрешение включается вручную. Экспорт требует абсолютного пути и `overwrite=true` для замены файла; хранилище не позволяет затереть существующую сборку библиотеки экспортом.

Проверки: `flutter test`, `flutter analyze`, `python tool/check_complexity.py`, `flutter test integration_test/mcp_editor_test.dart -d windows`. Сквозному тесту нужен отдельный `POB2_UI_HOME` с установленной совместимой парой. Проверяются вычисления PoB и управление приложением, не поведение сборки в игре.

# Repository Guidelines

## Структура проекта

PoB II — настольный интерфейс на Flutter для Path of Building 2. Точка входа — `lib/main.dart`. Модели лежат в `lib/domain/`, работа с сетью, процессами и хранилищем — в `lib/data/`, виджеты и управление состоянием — в `lib/ui/`. Каталоги переводов находятся в `lib/l10n/arb/`. Ресурсы приложения размещены в `assets/` и `docs/assets/`. Сайт и галерея находятся в `docs/`, сценарии сборки и проверки — в `tool/`, файлы установщиков — в `installer/`.

## Сборка и запуск

- `flutter pub get` загружает зависимости. Версия Flutter закреплена в `.github/workflows/ci.yml`.
- `flutter run -d windows` запускает приложение локально. На Linux и macOS укажите `linux` или `macos` соответственно.
- `flutter build windows --release` собирает выпуск для Windows. GitHub Actions также собирает Linux и macOS.
- `dart format --output=none --set-exit-if-changed lib test tool integration_test test_driver` проверяет форматирование, а `flutter analyze` запускает статический анализ.

## Стиль и архитектура

Пишите сообщения, документацию и комментарии по-русски. Используйте два пробела для отступов, `lower_snake_case` для файлов, `UpperCamelCase` для типов и `lowerCamelCase` для методов и переменных. Управляйте состоянием через Cubit или Bloc с неизменяемыми состояниями. Используйте records для компактных типизированных результатов, а pattern matching — для проверки структуры данных. Делайте функции короткими, а зависимости явными. Команда `python tool/check_complexity.py` проверяет предел когнитивной сложности 10 с учётом вложенных замыканий.

Игровые данные, правила и расчёты получайте из исходного Lua PoB. Храните исходники PoB и MCP отдельно от этого репозитория. Загружайте обновления в новый каталог, проверяйте пару компонентов запуском Lua и при ошибке сохраняйте рабочую пару.

## Тестирование

Модульные и виджетные тесты на `flutter_test` размещайте в `test/` под именами `*_test.dart`. Запускайте их командой `flutter test`. Сквозные сценарии находятся в `integration_test/`, например `flutter test integration_test/workspace_test.dart -d windows`. Для проверки с настоящим Lua и MCP выполните `dart run tool/smoke.dart --install`. Для загрузки компонентов нужны сеть, Git и 64-битный Python 3.11+. В отчётах указывайте, что этот сценарий проверяет расчёты в PoB.

## Коммиты и запросы на слияние

Начинайте тему коммита с русского глагола в неопределённой форме, например «Показать сравнение этапа прокачки в галерее PoB II». В запросе на слияние опишите причину изменения и выполненные проверки. Приложите ссылку на связанную задачу, если она есть, и снимки экрана при изменении интерфейса.

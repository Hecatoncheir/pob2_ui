# Установщики и обновление PoB II

Пользователь видит уведомление о новом выпуске и кнопку загрузки. Повторная загрузка продолжает `.part`, если сервер поддерживает диапазоны. Обязательны ожидаемое имя, адрес GitHub, размер и SHA-256. После проверки появляется «Перезапустить и обновить». Автоматическая загрузка включается отдельно; автоматического перезапуска нет.

Перед установкой сохраняются последняя рассчитанная сборка и незавершённый XML. Ошибка сохранения блокирует установщик. PoB/MCP и настройки лежат вне каталога программы; обновление оболочки не переключает пару игровых компонентов.

| Платформа | Пакет | Установка и обновление |
| --- | --- | --- |
| Windows x64 | Inno Setup `.exe` | Для текущего пользователя, без администратора. Стабильный запускатель и `versions/<версия>/`; ярлык открывает запускатель. |
| Linux x64 | Самораспаковывающийся `.run` | По умолчанию `~/.local/opt/pob2-ui`, без `sudo`; ярлык в меню приложений. Можно выбрать `--prefix /абсолютный/каталог`. |
| macOS Apple Silicon | `.dmg` | Перенос `PoB II.app` в Applications или `~/Applications`. Для встроенной замены нужен доступ на запись в родительский каталог; иначе открывается страница выпусков. |

## Проверка запуска и восстановление

На Windows/Linux установщик добавляет новый каталог и `pending-version`. Запускатель передаёт одноразовый токен новому Flutter-процессу. После первого кадра приложение записывает подтверждение. Только затем обновляется `active-version`, а старый номер становится `previous-version`. Если за 30 секунд подтверждения нет, кандидат завершается и запускается прежняя версия. Повреждённый или отсутствующий кандидат также не заменяет активную версию.

Для ручного возврата на Windows/Linux запустите корневой запускатель с `--rollback`. Каталоги версий пока не очищаются автоматически. Сам запускатель при обычном обновлении не заменяется: изменение его протокола требует отдельной миграции установщика.

На macOS помощник монтирует DMG только для чтения, проверяет идентификатор, версию и целостность подписи `.app`. Если прежнее приложение имеет Team ID, новый обязан совпасть. Предыдущая копия сохраняется как `PoB II.app.previous`; при отсутствии подтверждения запуска она возвращается. Нельзя переносить или удалять приложения во время обновления. При выключении питания между двумя переименованиями может потребоваться вручную вернуть `.previous` в `.app`.

Подтверждение первого кадра проверяет запуск оболочки. Совместимость компонентов проверяется отдельно настоящим Lua перед активацией новой пары. Это не испытание сборки в игре и не полная проверка пользовательских сценариев.

## Данные и зависимости

- Windows: `%LOCALAPPDATA%/pob2_ui`.
- Linux: `$XDG_DATA_HOME/pob2_ui` или `~/.local/share/pob2_ui`.
- macOS: `~/Library/Application Support/pob2_ui`.
- Явное переопределение: `POB2_UI_HOME`. Python: `POB2_UI_PYTHON`.

Установщики включают Flutter-приложение, но пока требуют Git и 64-битный Python 3.11+ для компонентов. На Linux/macOS MCP получает архив нативных библиотек из того же стабильного выпуска, что исходники, проверяет SHA-256 и распаковывает только разрешённые файлы. LuaJIT не устанавливается в систему. Поддерживаемые архитектуры: Windows x64, Linux x64, macOS arm64. PNG через GDI/Direct3D остаётся возможностью Windows.

## CI и выпуск

`ci.yml` закрепляет Flutter 3.50.0 и проверяет установку, запуск и откат пакета. Затем установленное приложение в отдельном профиле создаёт сборку, меняет экипировку, сохраняет XML и заметки. При повторном запуске проверяются восстановление сборки и совпадение показателей Lua. CI передаёт манифест уже скачанных компонентов. Linux запускается через Xvfb.

Релизный CI берёт теги и полные Git SHA из `tool/components-lock.json` на ревизии приложения. Windows, Linux и macOS проверяют одну пару, а фактические ревизии попадают в `components.json` в артефакте `ui-<платформа>`. При смене пары обновите в манифесте тег и SHA каждого изменившегося компонента. Обычный CI проверяет свежие стабильные выпуски. Локальная команда для закреплённой пары — `dart run tool/smoke.dart --install --lock tool/components-lock.json` с отдельным `POB2_UI_HOME`.

Для локальной проверки передайте `python tool/check_installer.py --target linux-x64 --components /путь/к/components.json`. С флагом `--build-check` без манифеста установленное приложение загрузит компоненты в новый профиль.

Для выпуска:

1. Обновите `pubspec.yaml` и `lib/domain/app_info.dart` согласованно.
2. Перенесите готовые изменения из «Не выпущено» в датированный раздел `CHANGELOG.md`.
3. Проверьте изменения и отправьте стабильный тег `vX.Y.Z`.
4. `release.yml` повторяет весь CI на теге, требует все три установщика, формирует `SHA256SUMS` и описание из changelog. Повторный запуск не перезаписывает опубликованный выпуск.

Пример локальных команд: `python tool/release.py --check-only`, `python tool/release.py --package windows-x64`. Inno Setup нужен только для сборки Windows-пакета; на GitHub runner он уже установлен. macOS и Linux упаковываются штатными средствами соответствующей ОС. Для обновления не требуется отдельный updater-пакет; управление состоянием интерфейса использует flutter_bloc.

## Подпись и границы доверия

SHA-256 обнаруживает повреждение пакета и сверяется с метаданными GitHub или `SHA256SUMS` того же выпуска. Это не отдельная подпись издателя и не защищает от захвата учётной записи публикации.

Сертификаты издателя не настроены. Windows может показывать предупреждение о неизвестном издателе. macOS CI использует локальную подпись ad hoc для проверки целостности; она не заменяет Developer ID и нотариализацию. Gatekeeper не отключается, карантин не снимается. Выпуски для широкой аудитории требуют отдельной настройки подписи Windows и Developer ID/notarytool для macOS. App Sandbox выключен для внешней поставки, поскольку приложение запускает Git, Python и отдельный Lua-процесс; системные механизмы защиты ОС сохраняются.

Идея проверки GitHub Releases и запуска установщика изучена в [LoreDub, update_installer.dart](https://github.com/Hecatoncheir/LoreDub/blob/0e1acad470c6f2b67dbfff61c905dcf63da48a21/lib/src/data/services/update_installer.dart). Здесь добавлены отдельное ожидание перезапуска, сохранение черновика, установка версий рядом и подтверждение запуска с возвратом прежней версии.
